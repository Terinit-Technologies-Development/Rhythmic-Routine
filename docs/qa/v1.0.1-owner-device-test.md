## 1. Owner Manual Build Instructions (PowerShell)

Execute the following commands in PowerShell from the repository root:

```powershell
# 1. Fetch and switch to the QA branch
git fetch origin
git switch qa/v1.0.1-device-validation
git pull --ff-only origin qa/v1.0.1-device-validation

# 2. Clean reproducible dependency install
npm ci

# 3. Clean native project prebuild (regenerates AndroidManifest with launcher queries and styles)
npx expo prebuild `
  --platform android `
  --clean `
  --no-install

# 4. Enter Android native build directory
cd android

# 5. Clean previous build artifacts
.\gradlew.bat clean

# 6. Compile canonical standalone QA APK
.\gradlew.bat assembleQaStandalone `
  -PreactNativeArchitectures=arm64-v8a `
  --console=plain

# 7. Return to project root
cd ..

# 8. Verify the standalone APK structure (must pass all standalone invariants)
node .\scripts\verify-android-qa-apk.mjs `
  ".\android\app\build\outputs\apk\qaStandalone\app-qaStandalone.apk"
```

## 4. Physical Device QA Test Matrix

Every hardware gate must be reported as `PASS`, `FAIL`, `NOT TESTED`, or `BLOCKED`.

### QA-01 — v1.0.0 → v1.0.1 Migration
- **Status:** NOT TESTED
- **Procedure:**
  1. Prior to installation, record existing Risk classifications, Risk Groups, Morning Buffer, Evening Wind-Down, cooldown settings, and history.
  2. Install candidate with `adb install -r`.
  3. Launch Rhythm (`com.terinit.rhythmicroutine.qa`).
- **Expected:**
  - Risk classifications preserved.
  - Risk Groups preserved.
  - Routine window times preserved.
  - Cooldown settings preserved.
  - Existing history preserved.
  - Existing Risk apps receive 30-minute default daily allowance.
  - Normal / Essential apps are not assigned daily allowances.

---

### QA-02 — Evening → Overnight → Morning → Open Day Continuity
- **Status:** NOT TESTED
- **Procedure:**
  1. Temporarily configure routine boundaries near the current wall-clock time:
     - Evening start: `now + 2m`
     - Evening end: `now + 4m`
     - Morning start: `now + 7m`
     - Morning end: `now + 9m`
  2. Test with at least two Risk apps (Risk A inside routine protected group, Risk B outside).
  3. Observe behavior across boundaries and while a Risk app is already in the foreground.
- **Expected:**
  - Evening starts → configured Risk protection applies.
  - Evening ends → NO Open Day; overnight protection immediately applies.
  - During overnight → ALL Risk apps remain locked.
  - Morning begins → Morning Buffer state applies.
  - Morning ends → Open Day arrives; routine-only restriction clears.
  - Transitions occur without reopening Rhythm.

---

### QA-03 — Default 30-Minute Daily Allowance
- **Status:** NOT TESTED
- **Procedure:**
  1. Confirm a migrated or newly classified Risk app displays `Planned 30 min`.
  2. Use the Risk app across multiple separate sessions (e.g. 10m, leave app, 8m, leave app, 12m).
- **Expected:**
  - Usage accumulates across sessions (`10 + 8 + 12 = ~30m`).
  - Usage does not reset between sessions.
  - Touch Grass triggers when daily allowance is exhausted (tolerance: ±60s).

### QA-05 — Access Lease Usage Counts
- **Status:** NOT TESTED
- **Procedure:**
  1. Use an app close to exhaustion (e.g. ~28m used of 30m allowance).
  2. Start an Access Lease (15m).
  3. Use the Risk app for longer than the remaining allowance.
- **Expected:**
  - Access Lease temporarily suppresses Touch Grass.
  - Usage continues accumulating into native ledger during lease.
  - Allowance becomes exhausted while lease remains active.
  - When lease expires, Touch Grass immediately presents if app is foreground.
  - Display reflects true used time (e.g. `32 / 30 min · allowance complete`). Usage is never clamped.

---

### QA-06 — Once-Per-Day Allowance Edit Guard
- **Status:** NOT TESTED
- **Procedure:**
  1. On Risk App A: increase allowance from `30 → 45 min`.
  2. Attempt a second edit on the same calendar day (e.g. `45 → 30` or `45 → 60`).
  3. Force-close and restart Rhythm, then attempt edit again.
  4. Reclassify `Risk → Normal → Risk`, then attempt edit.
- **Expected:**
  - First edit (`30 → 45`) succeeds.
  - Second same-day edit is rejected with domain explanation ("Editable again tomorrow").
  - Lock persists after app restart.
  - Reclassification preserves 45 min allowance and retains edit lock.

## 5. Stop Conditions

If any of the following occur during owner hardware testing, the candidate is **BLOCKED_BY_DEVICE_DEFECT**:

- Evening end returns to Open Day instead of overnight protection.
- Overnight window fails to protect all Risk apps.
- Morning end fails to release routine restriction.
- Daily usage fails to accumulate when Rhythm is backgrounded.
- Touch Grass overlay time counts toward Risk app usage.
- Access Lease usage is not counted in daily ledger.
- Daily allowance resets upon device/app restart.
- Second same-day allowance edit succeeds.
- Allowance increase `30 → 60 min` succeeds in a single edit.
- Installed-app discovery refresh clears the daily edit guard.
- Risk Group continuous session cooldown regresses.
- Essential apps become restricted.
- Insights displays mock/demo data on Android.
- Stale usage is displayed after native ledger failure.
- Returning from Usage Access settings requires app restart.
- Substantial double-counting occurs.
- Standalone APK requires Metro dev server.
